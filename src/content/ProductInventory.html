The reference build
The first module we built at the Pune plant, because it finds money on day one.

Stock was counted weekly, by hand, in each of six stores; nobody could say what a product line had consumed, or what was sitting in a corner since 2018. Inventory and material traceability went in first: every receipt, issue and return scanned, every lot linked to the work order that used it, every bin aged and valued. The dead-stock list came out of the first full count.

Questions store managers ask.

Our item master is a mess. Do we clean it first?
No — it gets cleaned inside the build, item by item, as the opening count happens. Cleaning it in Excel first is how these projects stall.
Do we need barcode printers and handhelds?
A label printer, yes. Handhelds, no — receiving, issue and count run on the phones your storekeepers already carry.
Can it handle six stores and two plants?
Yes; multi-location is standard, with transfers between them tracked like any movement.
Does it post to Tally?
Yes — receipts and issues post as vouchers, so the books and the floor stop disagreeing.
What happens to a write-off?
It's a task with an approver — usually the owner above a threshold you set — with the reason and the value logged.
Can this start before the full ERP?
It usually does. Inventory first, then orders and planning on top — every phase usable alone.
